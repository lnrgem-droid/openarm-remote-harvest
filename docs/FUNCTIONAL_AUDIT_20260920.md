# OpenArm 功能审查与实机验收记录（2026-09-20）

## 结论与范围

本轮按用户授权实际启动机械臂、受控归位、同步回位和本地录制，未仅依靠模拟。
保留原有功能：双机双臂遥操、重力补偿/已有力反馈、左从臂与夹爪保持、右主从保存姿态并一起回位、三相机预览、Jetson 本地录制、左右独立编号。未取消看门狗，未提高运动速度或跟踪误差限值，未改变控制器增益。

本次验收覆盖主要操作链，不代表不存在任何潜在缺陷；没有用软件测试代替夹持力、碰撞安全和人工手感验收。实际数据为约 10 秒的短 episode，并非连续 10 分钟性能准入。

## 修复内容

| 问题 | 修复 |
| --- | --- |
| 打开采集界面时，已有正常 HOLD/负载误差可能被误判，继而自动重启归位 | 复用健康控制栈；沿用控制限值 0.20 rad 判断跟踪健康。已有栈不健康则明确退出，不擅自归位。运行状态文案明确区分 FOLLOW/HOLD/回位 |
| SSH/ZMQ 无响应时部分启动/退出请求可能长时间卡住 | SSH 连接/保活超时；ZMQ 发送超时和 LINGER=0 |
| 保存姿态文件是合法 JSON 但根节点为数组/null 时崩溃 | 校验根类型，保留文件并报告不可用，不继续运动 |
| 保存姿态时未计入主夹爪速度；回位准备阶段主臂位置可能变化 | 静止判断包含夹爪；准备握手后重新核算主臂轨迹时长 |
| 回位后正在平滑恢复跟随，界面却没有解释为什么不能立即录制 | 状态增加 transitioning_arms；界面提示平滑衔接，后端继续拒绝过早录制 |
| 录制子进程退出早于相机封装完成，导致可以提前切换批次/开始新条 | 生命周期加锁，封装期间仍占用会话，完成后才解除采集锁 |
| 点击停止与相机激活线程竞态，可能重新创建录制标记 | 激活/停止使用同一锁，标记原子替换，已停止不再激活 |
| 相机停止写入时直接清空队列，静默丢失尾帧 | 停止哨兵排在已接受帧之后，排空队列、刷盘并生成本条 rgbd-complete.json |
| 使用全局上一条相机计数判定当前数据有效 | 必须读取当前目录的完整写入回执；缺回执/写盘错误/丢帧不标为有效成功 |
| 状态流中断仍可能重复旧机器人数据；异常时已采样数据丢失 | 校验有限数值、动作有效性和新鲜度；超时停止，尽可能封装已有 Parquet，异常返回非零 |
| 启动录制失败后残留活动条/采集锁，后续按钮一直不能使用 | 启动失败释放资源与锁，保留中止说明；关闭 PTY，避免文件描述符泄漏 |
| 不完整 episode 目录导致显示编号与实际编号不一致 | 恢复批次时同时扫描遗留目录，跳过已占用编号，绝不覆盖 |
| 异常请求可能杀死录制管理器，按钮全部无响应 | REP 接收后在异常边界内解析 JSON，错误返回后继续服务 |
| 控制命令被合法拒绝却显示为 SSH 断线；录制准备/封装文案混淆 | 保留连接状态并显示拒绝原因；明确区分准备、正式录制和封装 |

磁盘剩余空间改为检查用户选择批次所在的文件系统。无硬件测试使用临时运行目录和临时标记，避免测试改动真实录制状态。

## 实机与界面结果

1. 重启后受控归位 → ALIGN → RUNNING 实际完成。首次检查发现旧左臂 HOLD 目标与反馈相差约 0.84 rad，未当作正常状态继续；明确重建控制后误差回到限值内。
2. 右主从从初始位一起返回用户保存姿态，用时约 **12.65 秒**；主臂最大位移约 0.931 rad，从臂约 0.919 rad；最终自动恢复 FOLLOW。
3. 左臂 HOLD 期间，其七关节和夹爪下发目标保持不变；右臂运动不改变左臂保持目标。
4. 真机执行回位 → 中止 → 双端保持 → 解除回位伺服 → 再次回位，恢复 FOLLOW，无锁存故障。测试中在控制周期生效后核对保持目标，未将命令确认瞬间的旧 applied 快照误当作保持漂移。
5. 左右各录制一条，重复开始被拒绝；重复停止幂等。录制期间回位/切批次被拒绝；停止封装后采集锁解除，遥操仍 RUNNING。
6. 完整日常启动脚本复用已有控制栈，没有额外归位；真实 Tk 窗口按钮执行开始、中止、失败保存、结束会话通过。测试期间三路实时预览持续显示。
7. 原右臂起始位文件的 SHA-256 与修改前备份一致；原采集批次已恢复，未重置其左右编号。

## 交接与限制

- 正常使用原桌面“启动蘑菇采集控制台”；启动不会自动录制。
- 已有控制栈不健康时，现在会明确拒绝自动重启。确认物体已放置、主从路径安全后再显式重启遥操；这一步会归位，不能在夹持菌棒时盲目重试。
- 左臂保持不等于物理抱闸/断电保持；电源掉电、硬件故障不能靠软件保证不下坠。未进行破坏性断电测试，也未修改这项硬件限制。
- 完成录制只停止保存，不停止遥操。需要停运动时使用独立的保持/急停流程。
- 长时间满负载、真实菌棒接触力和人工双边反馈手感仍应现场确认；本轮不能宣称所有潜在 bug 永久消除。
