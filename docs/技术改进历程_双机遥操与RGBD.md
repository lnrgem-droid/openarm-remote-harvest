# OpenArm 双机遥操与三路 RGB-D 技术改进历程

本文记录本项目从 OpenArm 原始“**四根机械臂接在同一台主机**”的双边遥操程序，演进到“**主臂在 x86 主机、从臂和三台 RGB-D 相机在 Jetson**”的双机采蘑菇示教系统的技术路径。

它是开发复盘和协作交接文档，不替代真机安全规程。文中“已实现”表示代码和至少一次实际运行已经完成；“待验收”表示功能存在但仍需按场景做连续真机验证。

## 1. 初始条件与目标

原始 OpenArm 程序可以在同一台电脑上，通过四路 CAN 驱动一对主臂和一对从臂，具有重力补偿、归零和单机双边控制能力。它不直接解决以下项目需求：

- 主臂接 x86 主机，从臂接 Jetson，二者通过局域网遥操；
- 左对左、右对右，同时同步 7 个关节和夹爪；
- 从端三台 Orbbec（左腕 Gemini 305、右腕 Gemini 305、胸部 Gemini 335L）采集 RGB-D；
- RGB-D 优先在 Jetson 本地保存，主机只收低延迟 RGB 预览；
- 保存的数据未来可转换为 LeRobot 训练数据；
- 任何预览、录制或网络问题都不能直接抢占 CAN 或拖垮从端控制。

当前实际硬件映射为：

| 设备 | 右臂 CAN | 左臂 CAN |
| --- | --- | --- |
| 主机（主臂） | `can0` | `can1` |
| Jetson（从臂） | `can1` | `can2` |

主机与 Jetson 通过独立有线网段 `192.168.50.0/24` 连接，主机为 `192.168.50.1`，Jetson 为 `192.168.50.2`。相机按硬件序列号固定角色：左腕 `CV2L360000D9`、右腕 `CV2L360000NR`、胸部 `CP3294Y0001E`。

## 2. 架构演进

最终采用的核心原则是：**CAN 和实时电机控制只在各自本机存在；跨机器只传控制数据和状态数据；相机只由 Jetson 相机服务唯一打开。**

```text
主机（x86）                                      Jetson（ARM）
主臂 CAN0/1 → 主端重力补偿与控制网关 ─ UDP ─→ 从端控制网关 → 从臂 CAN1/2
                    ↑         ↓                    ↑
                 状态/诊断   动作目标            本地安全看门狗

主机 RGB 预览 ← ZMQ/JPEG（尽力发送）← Jetson 三相机 RGB-D 唯一服务
                                              ├─ 原始 RGB/Depth 本地落盘
                                              └─ LeRobot 状态/动作数据集
```

这样做的直接好处是：Jetson 即使失去主机预览连接，仍能保存数据；主机无法通过 ROS 话题误控制 Jetson CAN；相机、录制和预览也不会重复抢占同一台设备。

## 3. 已增加的主要功能与实现路径

### 3.1 Git 基线、分支与可回退开发

**做了什么**

- 将原始可用程序备份到 GitHub；`main` 保留原始基线。
- 在 `dev/remote-teleop-v1` 上进行双机遥操开发，每个关键阶段独立提交。
- 遥操稳定版本冻结为 `remote-teleop-v1.0`；RGB-D 工作从独立功能分支 `feat/jetson-rgbd-preview` 开始。
- 主机 x86 和 Jetson ARM 同步源码但分别编译、分别安装依赖，绝不复制 x86 的 `install/` 目录到 Jetson。

**解决的问题**：可以安全修改；某次调参或新功能出错时可回退到已验证遥操基线，不会损坏原始程序。

### 3.2 双机 UDP 主从遥操

**做了什么**

- 新增主端 UDP 网关和 Jetson 从端 UDP 网关，控制/状态频率为 250 Hz。
- 本地重力 PD 电机环保持 500 Hz；高频 CAN 命令不经过网络。
- 主机持续发送左右臂 7 关节目标和夹爪目标；Jetson 返回从臂实际位置、目标、误差、状态和故障信息。
- 明确了消息版本、会话 ID、单调时间、序列号、关节顺序、单位和超时处理。
- 为避免跨机 ROS 自动发现形成“隐性第二控制链路”，两侧 ROS 图隔离，跨机仅保留 UDP。

**实现思路**：不用 ROS topic 跨机器直接驱动从臂。ROS 只在本机连接控制器；网络包只表达动作意图，从端再根据本地状态决定是否执行。

### 3.3 受控归零、相对对齐与安全状态机

**做了什么**

- 复用原始程序的启动位姿/归零能力，启动时受控回到既有编码零位，且不改电机零偏置。
- 加入相对位姿参考：主从归零后捕获参考姿态，之后跟随的是主臂相对参考位姿，避免启动瞬间因绝对编码差产生跳变。
- Jetson 看门狗状态机：`INIT → ALIGNING → READY → RUNNING → FAULT/E_STOP`。
- 新会话、重启和故障恢复后必须重新对齐并显式 `run`，不得自动恢复动作。
- 支持 `status / align / run / hold / reset / disable` 本地控制命令；正常停止流程是 `hold → 现场托举 → disable`。
- 加入关节速度限制、最大跟踪误差以及超时保持策略；后续根据实际遥操手感对速度限制进行了放宽。

**关键原则**：网络超时、进程心跳和控制周期异常只能让从臂进入“位置保持并锁存故障”，不能把旧动作继续执行。真正的急停力矩状态仍需按机械安装、重力方向和负载做真机确认，软件不能武断地一律断力矩。

### 3.4 重力补偿与双边反馈试验

**做了什么**

- 两端均保留原始 OpenArm 重力补偿；这是人工拖动主臂和从臂稳定保持的基础。
- 接入有限的双边反馈/阻尼实验，使从臂接触阻力能在主臂侧体现。
- 针对“主臂阻力过大、像在对抗延迟后的从臂状态”的现象，减弱了直接位置对抗成分，保留更可拖动的反馈形式。

**当前边界**：遥操和重力补偿已实际调通，但双边力反馈尚未形成适用于蘑菇采摘的最终参数表。特别是 J2–J7 的重力感、阻尼、夹爪夹持反馈仍需要按安装姿态和夹指反复标定。

### 3.5 三台 Orbbec RGB-D 的唯一相机服务

**做了什么**

- Jetson 使用 `pyorbbecsdk` 为每个相机建立独立 Pipeline，按序列号绑定角色，不依赖不稳定的 `/dev/videoN` 顺序。
- 三台相机均启用 `640×480 @ 30 FPS` RGB 和 Depth，并在单个 FrameSet 内完成 Depth-to-Color 对齐。
- RGB 固定为 `uint8 (H,W,3)`，Depth 固定为 `uint16 (H,W,1)` 毫米值；无效深度为 `0`。
- 相机服务是唯一设备打开者。录制器、主机预览和后续界面只订阅其输出，不再各自打开相机。
- 每帧保存设备时间、Jetson 单调时间、系统时间、序列号、stride、格式、Depth scale 与 RGB/Depth 配对误差。

**为什么这样做**：三台 USB 相机最容易出现设备抢占、帧错位和不可复现的角色交换；固定序列号与唯一打开者是稳定运行的前提。

### 3.6 Jetson 本地 RGB-D 录制与 LeRobot 接入

**做了什么**

- Jetson NVMe 本地保存三路原始 RGB 和无损 Depth，文件旁配套 JSONL 时间戳/序列号元数据。
- LeRobot 记录从臂实际状态 `observation.state` 和真正应用的 `action`，采样实测为约 30 FPS。
- 录制器不重复初始化 CAN，不抢走从端控制权；以 `control_authority=external` 方式只读状态和动作。
- 每次录制创建独立目录 `~/datasets/openarm_rgbd_YYYYMMDD_HHMMSS`；空间不足时拒绝新 episode 或安全结束。

**当前数据形态**：状态和动作已是标准 LeRobot Parquet；三路 RGB-D 先以高保真 raw sidecar 保存。这降低了 Jetson 同时写入六路图像时的阻塞风险，也完整保留了后续按时间戳重采样/转换的依据。

### 3.7 主机实时三画面 RGB 预览

**做了什么**

- Jetson 只把低优先级 JPEG RGB 通过 ZMQ TCP 端口 `5556` 发到主机；不传 Depth。
- 主机提供中文实时预览界面，胸部相机在第一排，左右腕部并列在第二排；可显示 FPS、帧龄和连接状态。
- 非录制时目标预览为 15 FPS；开始本地录制时自动降为 10 FPS，给本地写盘让路。
- 消息队列只保留最新帧，网络拥堵或主机退出时主动丢预览帧，不积压历史画面。

**已测结果**：录制中预览约 10 FPS 时，最近一次 44 秒和 22 秒验证中，三路 RGB-D 本地保存约 `29.76–29.92 FPS`，LeRobot 状态/动作记录 `30 FPS`，写入丢帧为 `0`。

### 3.8 资源隔离与“停止录制不停止遥操”修复

**问题**：最初点击“停止并保存”后，Jetson 在视频/元数据收尾阶段会出现瞬间 CPU、NVMe I/O 压力，触发从端安全看门狗的本地控制周期超时。遥操因此进入 `FAULT`；这不是操作按钮主动停止遥操，而是独立保护正确介入。

**修复路径**

- Jetson CPU `0–2` 专用于从臂控制、UDP 网关和看门狗。
- CPU `3–7` 专用于相机服务、LeRobot 录制、编码、记录管理器和 bridge，并降低录制进程优先级。
- 停止录制时先立即关闭 RGB-D 原始 spool，再让 LeRobot 完成其元数据收尾，缩短高 I/O 重叠期。
- 看门狗仍保留网络动作 150 ms 的严格超时；对本地进程心跳/控制周期的阈值基于压力测试放宽到合理范围，避免正常收尾被误判。

**压力验证**：在相机采集运行时，对 Jetson 非控制核施加负载，控制核 250 Hz 循环的 p99 抖动约 `1.225 ms`。这证明隔离方向正确，但最终仍应在真实双臂运动、录制、停止录制的组合下做连续验收。

### 3.9 日常启动与现场检查

**做了什么**

- 添加桌面入口：`启动主从遥操`、`启动主从遥操并采集 RGB-D`、`OpenArm 到场检查`。
- 启动前自动检查主机 CAN、Jetson CAN、固定 IP/SSH、相机服务、磁盘空间和录制状态。
- RGB-D 一键启动复用与“仅遥操”完全相同的遥操核心，避免两套启动逻辑逐渐偏离。

**仍需改进**：启动日志一度出现“显示 RUNNING，但实际主从不跟随”的情况。进程和看门狗状态已经能显示 RUNNING，但还缺少“动作数据确实持续到达从端并被实际控制器消费”的启动后闭环验证。这是当前优先修复项。

## 4. 主要踩坑与经验

| 现象 | 根因 | 处理与经验 |
| --- | --- | --- |
| 从臂自行上抬、乱动 | 主从参考位姿、自动归零与看门狗状态切换叠加；曾出现不正确的状态恢复路径 | 启动后只允许 `ALIGNING`，相对参考在对齐后捕获，必须显式 `RUN` |
| 小角度主臂动作从臂不跟 | 速度/增量限幅过保守，且主从初始差和滤波会吞掉小指令 | 在安全单关节测试后放宽限制；依然保留最大误差和超时保持 |
| 主臂阻力过大、手感差 | 双边反馈直接耦合了有网络延迟的从端位置/重力状态 | 将反馈与主从位置跟随解耦，先保证可人工拖动，再逐关节调阻尼/反馈增益 |
| Jetson 重启或短时卡顿 | ARM 环境、USB、相机与控制共享资源 | x86/ARM 独立构建；相机和录制 CPU 隔离，控制保留独立核心 |
| 相机画面看似回放 | Rerun 时间线停留在历史时间/旧 recording，而不是新 live stream | 明确使用实时 ZMQ 订阅器，启动时切到最新时间；预览只显示最新帧 |
| 三路 RGB-D 录制只有约 7.7 FPS | 六路图像落盘在 Python 主循环同步执行；自定义 IPC 流未被 LeRobot 原生相机线程识别 | 改为异步写入、raw spool 与 LeRobot 状态/动作分离，最终恢复到约 30 FPS |
| 停止录制后遥操 FAULT | 录制收尾抢占 CPU/NVMe，触发本地控制周期看门狗 | CPU 集合隔离、降低编码优先级、提前关闭 spool；需继续真机组合验证 |
| 原先所有臂在同机，迁移后 CAN 数量变化 | 曾把旧 `can0–3` 映射直接套用到新接线 | 每次上电明确检查：主机只有主臂 `can0/1`，Jetson 只有从臂 `can1/2` |
| 一键脚本卡在归零等待 | 归零“命令发出”与“电机已经 ready”的判定混淆；硬件启动时序不同 | 脚本按控制器 ready、稳定对齐窗口、看门狗状态分阶段等待，并保留日志供定位 |

## 5. 当前版本能力边界

### 已可用于

- 两人现场保护下的低速双机双臂示教遥操；
- Jetson 本地三路 RGB-D、从臂状态和 applied action 同步采集；
- 主机通过三画面 RGB 实时观察从端；
- 为蘑菇采摘收集原始高保真示教数据。

### 不能宣称已经完成

- 生产级功能安全认证；Jetson 断电/死机时的最终机械安全状态仍依赖机械结构和现场急停；
- 长时间、满负载、带真实采摘负载的双边力反馈稳定性；
- 已将 RGB-D 转换为可直接用于训练的标准六路 LeRobot 图像特征；
- 自动抓菌棒、采蘑菇、放篮筐的训练策略和真机自主执行；
- 所有上电条件下 100% 可靠的一键启动。

## 6. 下一阶段建议

1. 修复一键启动的“RUNNING 假阳性”：启动后验证 UDP 动作序列持续更新、从臂实际反馈变化、控制器心跳健康；任一失败则明确退出并提示日志。
2. 做“遥操 → 开始录制 → 停止保存 → 继续遥操”至少 10 分钟真机验收，确认资源隔离有效。
3. 编写离线 RGB-D 转换器：以 raw sidecar 的真实时间戳，将六路视觉按规则注入标准 LeRobot Dataset，并生成质量报告。
4. 制定菌棒夹持、蘑菇夹取/拔取、投篮的分任务示教规范，先采高质量、可重复的数据，再训练策略。
5. 在真实末端夹指、移动底盘升降杆和温室环境中重标定重力补偿、关节限制与力反馈参数。
