# 右主从臂保存位置回位提速

仅调整采集界面“右臂回到保存的初始位置”（`right_return`），不改变启动自动归位、
正常遥操、力反馈、左臂保持或录制流程。保存的姿态文件无需重新设置。

- J1–J7 回位轨迹峰值速度：从 0.15 提高至 0.20 rad/s。
- 夹爪回位速度仍为 0.25 rad/s。
- 保留五次平滑插值、至少 2 秒轨迹时间及到位稳定检查。
- 同时根据主臂和从臂的行程计算共同轨迹时间；主端退出旧回位状态后重新读取位置，
  如主端行程变大，仍按相同速度上限延长轨迹，不能只修改从端计算。
- 保留左臂必须 HOLD、录制期间禁止回位、主臂伺服握手、0.20 rad 跟踪误差保护、
  超时/断连中断以及回位结束后恢复跟随的握手。

关节行程主导且不触及 2 秒下限时，理论轨迹时间缩短约 25%。例如最大关节行程
0.5 rad，轨迹时间从 6.25 秒降至 4.6875 秒。实际按钮到完成时间还包含握手和
到位确认；夹爪行程主导时不一定缩短。提速会增加运动加速度，不能等同于已完成
各种负载和姿态下的实机验收。

修改位于 `remote_teleop_runtime/collection_motion.py` 的 `RETURN_SPEED_RAD_S`。
软件模拟覆盖每个关节和夹爪、主从不同初始行程、握手后主端位置变化，以及已有
停止/断连/跟踪误差保护测试。本次不自动发运动指令。

安装后需在路径清空、夹爪无物体、现场准备好后重新启动遥操控制栈才生效。
只关闭并重开采集窗口可能复用旧进程，不能保证加载新代码；不要在夹持时重启。
首次测试应先用小行程确认主从平滑同步，再逐步增加行程。

## 到位后未自动恢复跟随：后续修正

现场只读状态显示总体RUNNING、无安全故障，但右臂HOLD，记录为“回位误差超限或超时”。
从臂距保存实际位约0.031rad，主从J3/J6仍有约0.080rad差；旧提示未区分超差和到位超时，
因此不能追溯性地断言当时触发了哪一个。该运行进程早于提速代码安装，不能归因于提速。

源码检查发现：

1. 主端回位采用启动PD增益，但此前明确禁用了启动已有的限幅跟踪补偿，无法消除部分
   姿态的静差。现在仅在回位伺服健康且启动补偿开关开启时使用同一限幅补偿；无积分、
   无编码器/保存位置偏移；真实反馈过期、回位故障锁存或归位失败时不启用该补偿。
   正常主臂FOLLOW仍关闭位置补偿，保留重力补偿和原力反馈，不增加正常遥操刚度。
2. 上次提速遗漏了主臂C++控制器内部0.15rad/s限速。现统一至0.20rad/s，并增加
   Python轨迹速度与C++限速一致性测试，避免两端速率分歧。
3. 保留原0.20rad跟踪保护、到位容差、0.5秒稳定时间、主臂解除伺服确认和
   平滑恢复FOLLOW流程；不以扩大误差、自动重试或清故障解决回位失败。
4. 状态新增`collection.return_detail`，记录计划时长、已运行时长、主/从最大偏差关节、
   偏差数值和主从对齐差。超差、到位超时分别提示，失败时保留诊断快照。

主机软件回归128项、Jetson相关回归49项通过，两端独立编译和ROS环境下动态库检查通过。
模拟覆盖旧主臂静差导致超时、受限补偿后通过到位门槛、
伺服释放握手后进入FOLLOW，以及每个关节/夹爪的主从不同轨迹长度和峰值限速。
模型不包含全部摩擦、重力辨识误差和真实网络时序，软件通过不能代替真机验收。
## 本次受控真机验收

用户确认夹爪已清空、允许四臂归位后，重启原 `openarm-remote-teleop.service`。
四臂启动归位、两轮对齐和32电机真实使能检查通过，确认新控制栈RUNNING。
随后调用与界面相同的 `left_lock`、`right_return`，不注入假关节反馈，也不重写保存位置。

- 使用原保存位置（`saved_unix_s=1789891997.7249405`）。
- 回位计划轨迹11.079秒；约11.845秒后完成到位确认和伺服释放、恢复FOLLOW。
- 恢复FOLLOW后连续观察5秒，共记录全流程307组状态，无故障。
- 回位期间采样最大主端目标偏差0.03423rad，从端目标偏差0.04324rad。
- 结束时右臂主从最大关节差约0.809°；下发七关节目标与主臂读数差为0。
- 最终RUNNING、fault_bits=0、左臂HOLD、右臂FOLLOW、回位阶段idle、无录制。
- 左臂保持目标全程未改变，原保存位置完整保留。

原始记录：`validation/20260920-return/acceptance.json`。
验收工具：`scripts/validate_right_saved_return.py`，只有显式`--execute`才会发起一次实体回位；
必须先人工确认空载、安全路径和急停可用，不应作为后台定时任务运行。

这是一次空载保存姿态回位及自动恢复跟随验收，不代表所有负载、姿态和网络异常均已实测。
没有人为阻挡机械臂、切电或断CAN；人工推动主臂后的手感仍由现场操作者复测。
