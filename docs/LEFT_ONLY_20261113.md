# 单左臂遥操：笔记本主臂 + Jetson 从臂（2026-11-13）

这是独立的**左主臂 → 左从臂**版本，包含左夹爪和左臂力反馈。右主臂和右从臂均不创建控制器，不参与使能、归位、反馈预检或运行状态判定。保留真实左臂的关节名、运动学和原有左臂增益。

本次只完成离线代码、编译和自动化检查；尚未在 Jetson/机械臂上完成现场验收，不能把安装成功视为机械臂可以直接高速使用。旧的双臂采集 GUI、右臂回位/采集按钮、双臂录制流程不适用于本版本。这里提供终端遥操入口，没有把左臂伪装为右臂。

## 1. 明天先安装，两端电机不用上电

同一个 `openarm-left-only-20261113.tar.gz` 放到两台机器。包里是源代码，不含笔记本 x86 二进制；Jetson 会在本机编译 ARM64。依赖现有 ROS 2 Humble、colcon、C++ 依赖和旧工作空间，不会在线下载依赖，不会覆盖旧代码/安装目录，不会启动或设置服务开机启动。

在 **Jetson（nvidia 用户）** 执行：

```bash
cd ~
tar -xzf /实际路径/openarm-left-only-20261113.tar.gz
cd ~/openarm-left-only-20261113
python3 scripts/install_left_only.py --role follower --follower-bus can2
```

在 **笔记本（openarm 用户）** 执行：

```bash
cd ~
tar -xzf /实际路径/openarm-left-only-20261113.tar.gz
cd ~/openarm-left-only-20261113
python3 scripts/install_left_only.py --role leader --follower-bus can2
```

默认 SSH 别名 `openarm-jetson`，Jetson 有线地址 `192.168.50.2`，Jetson 包目录 `/home/nvidia/openarm-left-only-20261113`。不同环境用安装器的 `--peer`、`--peer-ip`、`--peer-root` 设置；旧工作空间不在默认位置时加 `--underlay /实际路径/ros2_robot/install`。双方 `--follower-bus` 必须一致。

每次编译使用包内源码，输出 `ros2_robot/install_left_only`；服务引用解压目录，安装后不要移动或删除该目录。不要解压覆盖正在运行的版本。安装失败时保留报错和 `ros2_robot/log_left_only/`，不要继续启动。

## 2. 断电确认接线，停掉旧控制，再只给左臂供电

你今天交换过 Jetson 两根 CAN 线，不能只按 `can1/can2` 名字判断物理左右。默认布局为：

| 设备 | 本版本使用 | 不控制 |
|---|---|---|
| 笔记本主臂 | 物理左主臂 `can1` | 物理右主臂 `can0` |
| Jetson 从臂 | 物理左从臂 `can2` | 故障右从臂 `can1` |

先可靠支撑四条臂，切断电机电源，再核对/恢复接线。故障右臂保持可靠支撑、断电；需要拔插时只在断电状态操作。若物理健康左从臂确实接在 `can1`，两端安装命令均改为 `--follower-bus can1`；脚本不会自动猜测或换线。

在电机断电、各臂可靠支撑时关闭原来的双臂启动终端/GUI及其控制服务。不要在旧服务仍运行时给电机重新上电。新版本预检会拒绝任何现存机械臂控制进程，但不会擅自停止它们。

本版本不自动配置或重置 CAN。所选左臂接口必须已按原流程配置为 CAN FD，仲裁 1 Mbit/s、数据 5 Mbit/s，状态 UP / ERROR-ACTIVE。检查：

```bash
# 笔记本
ip -details link show can1
# Jetson（如配置物理左臂为 can1，这里也用 can1）
ip -details link show can2
```

只给健康左主臂、左从臂上电。不要使用“跳过预检”或改故障码的方式启动。

## 3. 笔记本预检与启动

两端安装完成，有线网络和免密 SSH 正常后，在笔记本新目录执行：

```bash
cd ~/openarm-left-only-20261113
python3 scripts/left_only_session.py check
```

`check` 只发读取参数和查询反馈的 CAN 指令，不使能、不清错、不运动。它检查：

- 两端源代码清单一致、各自编译文件校验通过，无旧控制进程。
- 所选 CAN 盒身份/速率正确，所选臂 8 颗电机连续 3 次返回失能状态 0。
- 左从臂 J1 的只读参数与今天记录的健康左 J1 匹配，防止接到故障右臂；不会写入或复制电机参数。更换电机或标定参数后需重新核实身份，不能直接删除该检查。

预检通过，人员在场确认左主从臂运动范围清空、右臂隔离、可随时停止后执行：

```bash
python3 scripts/left_only_session.py start --workspace-clear
```

**该命令会使能左主臂和左从臂，并以各自启动时测得的关节位置保持，不再执行固定姿态归位。** 启动前让主从臂自然垂落、姿态对应并静止；保留主从误差、新鲜反馈、电机健康与连续一秒稳定检查，通过后进入原有绝对位置跟随。姿态差过大时拒绝跟随，不自动抬臂对齐。通电后仍有重力补偿和位置控制，可能存在轻微调整；这不是电机重新设置零点。

成功会打印“左臂启动检查通过”。首次现场验收先小幅、低速逐关节和夹爪检查方向、跟随及限幅，再在可靠支撑、人员可立即处置的条件下验证断联保持。未完成现场验收前，不做高速、大范围或带负载作业。

## 4. 查看、暂停、正常停止

```bash
python3 scripts/left_only_session.py status
python3 scripts/left_only_session.py hold
```

`hold` 请求从臂保持最后目标，不是断电；左主臂仍可能带重力补偿。保护触发后不会自动恢复跟随。本版不提供在线 reset 或 hold 后直接 run：排查后支撑、失能、停止，再重新启动并原位保持。

**先可靠支撑左主从臂**，再正常停止：

```bash
python3 scripts/left_only_session.py disable --arms-supported
```

命令仅请求左主从控制器失能，连续读取所选 16 颗电机确认状态 0 后停止新服务。通信失联或部分启动失败导致该命令失败时，不要把报错理解为“已经失能”：先现场支撑，按现场停机流程切断电机电源，再停止残留服务。切断电源可能使臂下落，支撑不可省略。

启动失败时脚本会尝试请求保持；控制器可能仍使能，也可能因进程退出而失能。**失败不是安全停止证明**，不要重复点 start 或直接杀进程；现场支撑后处理。

## 技术边界

- 独立 UDP 50110/50111、ROS domain 71、Unix sockets `/tmp/openarm_left_runtime.sock` 和 `/tmp/openarm_left_watchdog.sock`，避免旧双臂 UI 路由到本会话。仍禁止两个控制程序共用同一机械臂 CAN 总线。
- 保留旧双臂默认参数和逻辑；新增 `--left-only` 模式，右控制器关闭。消息内部仍保留原 16 轴协议结构，右侧占位数据不发布到任何右臂控制器，不是双臂数据集。
- 被动 CAN 监听检查每条活动左臂全部 8 颗电机的真实反馈。运行中状态异常（包括 4）、失能、CAN 错误或反馈丢失会锁存保护；主臂停止新动作发送，从臂停止跟随并请求保持。软件保持无法让故障/断电电机恢复承载能力。
- 硬件型号、状态 4 的厂家含义仍应以 DM8009P 对应固件手册/厂家诊断为准。本版本隔离故障右臂，并没有修好它。
- 使用指定会话脚本启动；不要绕过预检直接执行 ros2 launch、通用双臂脚本或手动使能工具。

## 2026-11-14 启动时恢复旧会话

启动先验证两端版本，再判断现有会话。健康 RUNNING 直接返回，不重复使能。已锁定故障且两端 16 颗电机连续三次状态均为失能时，再次确认状态并停止旧服务，然后重新进行完整预检。电机仍使能或初始化尚未结束时，返回 NEEDS_ARM_SUPPORT（退出码 3）；桌面菜单和采集界面提示支撑两臂，用户确认后通过 `start --workspace-clear --arms-supported` 先失能停止，再执行原位启动。未知反馈、电机异常码、通信失败或版本不匹配均不自动放行。

恢复期间仅查询 0xcc 状态，不对运行中的控制器查询标识寄存器，避免寄存器回包被旧监测误判为电机失能。停止后原有完整预检仍会核对从臂身份。启动/停止/保持操作使用互斥锁；状态查询和“仅预检”不清理服务。旧终端进程缓存旧入口，请关闭后从桌面重新打开。
