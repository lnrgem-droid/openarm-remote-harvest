# 全自动启动检查、归位对齐与静态精度验收

## 操作

机械臂上电，电源稳定、急停按正常流程解除、四臂运动范围内无障碍及夹持物后，
双击原桌面入口。新启动自动依次执行：

1. CAN、网络及服务检查。
2. 重新初始化需要恢复的控制栈，按原受控轨迹让从臂、主臂依次回初始位。
3. 确认四臂均**实际到位**，并读取主从共 32 个驱动的实际使能状态。
4. 自动检查左右各七关节的主从差值、初始位偏差以及反馈新鲜度，要求连续静止一秒。
5. 只发送一次 ALIGN，轮询 READY；随后自动 RUN 并解除启动位保持。
6. 在正常跟随增益下再检查主臂位置、下发目标和从臂实测位置，连续静止一秒。
7. 再确认驱动全部使能，才输出最终“现在可以遥操：是”。

中间无需人工摆臂或输入 ALIGN/RUN。旧栈仍运行但全体驱动断电失能、双方 FOLLOW、
无故障/录制/姿态过渡时，重新点击启动会显示三秒恢复提示并自动走同一流程；
不是在后台发现掉电后擅自重新使能。部分掉电、故障、急停、HOLD 或录制中仍拒绝自动恢复。

已经通过本次会话验收且正在正常遥操时，重复打开采集界面保留现状，不突然归位。
没有相同 leader_session_id 验收记录的旧 RUNNING 不视为已验收。仅遥操与采集入口共用核心。

## 明确的数值合同

配置为 `scripts/startup_alignment_policy.json`，单位为弧度：

| 检查 | 门槛 |
| --- | --- |
| 初始位 | J4=π/5，其余关节=0；保留原电机零点 |
| 四臂各自距离初始位 | ≤0.07 rad，沿用已有归位门槛，不放宽 |
| 左右每组 J1–J4 主从差 | ≤0.05 rad（约2.86°） |
| 左右每组 J5–J7 主从差 | ≤0.035 rad（约2.01°） |
| RUN 后下发目标相对主臂 | ≤0.005 rad（约0.29°），防止目标偏置或裁剪被忽略 |
| RUN 后目标相对从臂 | 同各关节主从差门槛 |
| 静止窗口 | 连续≥1秒、≥6份状态，各主从关节变化范围≤0.01 rad |
| 新鲜度 | 动作/反馈均≤100ms；状态不可故障、会话不可更换 |
| 每次静态验收超时 | 12秒；超时失败，不反复归位、不自动加力 |

上述精度门槛是本项目初始验收配置，不是 OpenArm 官方保证值或驱动标定精度。
夹爪包含在使能检查中，但本功能不会自动夹紧/松开以标定夹爪，也不声明已验证夹持力。

## 修掉的错误判定

- 旧逻辑统计 `Startup homing command complete.`，但超时也会打印该行。
  新逻辑只接受四臂真正到位的日志；遇到 `Startup homing timed out` 即退出启动。
- 旧 ALIGN 的0.15 rad约8.6°仅是粗安全门槛；新增独立精度验收，不修改安全状态机来放行误差。
- 启动保持使用的增益与正常遥操不同，必须在切换后复测，不能仅以归位时对齐作为最终成功。
- 验收记录绑定主臂会话，不能以旧文件证明新启动已成功。

## 报告和失败处理

主机 `/tmp/openarm-remote-teleop/`：

- `alignment-aligning.json`：进入 ALIGN 前的14关节实测与问题列表。
- `alignment-following.json`：正常跟随模式下的14关节实测与通过/失败结果。
- `alignment-following.pending.json`：本次尚未完成最终使能检查的结果，失败时供诊断；不能作为复用凭据。
- `motor-enable-status.json`：主从32个驱动状态。
- `leader.log` 及 Jetson `/tmp/openarm_bimanual_follower.log`：实际归位结果。

无法到位或误差超限时走已有保持清理路径，不自动关闭从臂力矩、不重置编码器、不加角度偏置、
不自行提高增益，也不反复发送归位轨迹。路径安全不代表电机有能力克服摩擦或负载。

特别说明：此前左臂归位记录出现过约0.11 rad偏差，J7在部分姿态也有数度静差。
这些物理偏差**不会因加了验收程序而消失**；再次出现时新流程会明确拒绝进入遥操，
需要继续检查负载/补偿/控制参数，不能宣称已自动标定好或保证任何姿态都完全一致。

本次实现验收以模拟轨迹、真实 Bash 分支和只读状态检查为范围，没有执行真机归位。
首次完整归位及动态跟随仍须实测；此功能也不替代运行时看门狗和物理急停。

2026-09-20 验证结果：主机完整相关回归105项通过；Jetson新增启动/对齐测试37项通过。
Jetson系统pytest自动加载的第三方anyio插件与其pytest版本不兼容，测试时仅对该命令
设置 `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`，未更改系统环境或安装包。
通过SSH执行真实只读验收，当前未对齐姿态被正确拒绝，报告能指出左右腕部的具体超限关节。
