# 2026-10-04 遥操与采集更新

本次同步包含此前未推送的遥操修复、左右主臂自动对齐、手动结束录制及接收队列超时修复。

## 分支与部署

- `dev/remote-teleop-v1`：主从控制、协议、本地看门狗、启动/停止工具及其测试。
- `feat/jetson-rgbd-preview`：RGB-D 服务、录制管理器、采集控制台及其测试。使用新版控制台时，需要同时加载上述遥操分支的控制器。

双机部署需同步主机与 Jetson 的源码，并按原部署流程构建/安装实际使用的 ROS overlay。Python 运行时新增 `kernel_rx.py`，不要只复制 `follower.py` 或界面文件。确认实际启动的 overlay 包含最新模块后，才能加载更新。正常重启会让四臂归位，需要操作者先清空运动范围、放好夹持物并保持主臂静止。

## 操作变化

开始录制后，当前条编号保持不变，由操作者点击“成功并保存”“失败并保存”或明确中止结束。真实故障导致停采时，保留原编号及已录数据，等待保存结果；中断条目即使标记成功，也不会成为有效成功数据。

左从臂保持期间，可以低速自动移动左主臂及夹爪对齐，再恢复左臂跟随；右侧同理。自动动作需界面确认，控制器必须实际报告支持。恢复跟随需要对齐完成、主臂伺服释放确认及新鲜反馈；不会自动开始录制。

录右臂需要左臂保持、右臂跟随，无需恢复左臂跟随。“保存主从起始位”与“主从一起回位”仍沿用既有受控流程。

## 通信修复与验证边界

故障表现为录制期间进入 `FAULT: leader action receive timeout`，按钮随之禁用。旧版在接收预算耗尽、队列持续非空时可能不发布仍然新鲜的动作。先前仅修正“预算耗尽即丢包”不足以覆盖该情况。

生产接收改用 Linux `SO_TIMESTAMPNS_NEW` 的每包到达时间，在保持有限处理预算的同时判断包的新旧。固定保守时钟转换不重新标记旧包；明显系统时钟跳变、缺失/无效时间戳不会赋予新动作权限。命令会话隔离和故障锁存保留。100ms 动作新鲜度、150ms 断流保护、250ms 控制周期保护以及归位和电机参数不因本次通信修复放宽。

验证结果：

- 通信修复与遥操运行时相关回归：429 项通过。
- Jetson 隔离模拟：接收延迟注入，与真实录制程序的成功/失败保存及三路合成 RGB-D 写盘同时运行 60 秒；通信保持 RUNNING。
- 三轮 10 秒写盘，每路每轮 300 帧，零丢帧。模拟真实断流后约 156ms 触发 FAULT，恢复发送不自动解除。
- 经现场确认，正常重启和四臂归位成功，32 个电机使能并反馈新鲜。
- 加载后在合成录制/写盘负载下观察真实遥操链路 65 秒，130 次采样均正常，最大采样动作龄期约 22ms，未再次 FAULT。未替操作者执行采摘动作；这不是无限时长或零调度抖动保证。
