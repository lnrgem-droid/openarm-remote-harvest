# 现场独立恢复遥操启动失败

本功能只恢复机械臂遥操会话，不解决反复出现的指令接收延迟。
不修改关节增益、超时门限、CPU 分配，不退出导航、建图、RViz 或相机服务。

## 控制台操作

更新后的按钮名称为“断电后清理遥操故障…”。已打开的旧界面需要关闭后重新打开，
无需重启电脑。普通关闭窗口并不代表电机失能。

1. 发生 `leader action receive timeout` 后，停止采集，放下夹持物并稳固支撑四臂。
2. 先点击“停止遥操并失能…”。成功后可以按正常流程重新启动。
3. 如果提示失能服务不可用，尤其是在启动验收失败、主臂控制进程已退出后，
   保持四臂支撑，实际关闭主臂和从臂两端的机械臂电机电源。
4. 笔记本、Jetson 保持开机。录制必须保存完成、录制器空闲。
5. 点击“断电后清理遥操故障…”，阅读弹窗，并只在实际断电后确认。
6. 等待“旧会话已清理”。清理期间持续保持电机断电。
7. 恢复电机电源，确认四臂空载、归位路径无人无障碍，再单独点击“开始主从遥操…”。
   等待归位、对齐及 32 个电机使能核验全部通过后才能操作。

清理失败时保持电机断电，按具体提示处理；不会自动重试、自动清故障后恢复跟随。
反复超时不能靠反复启动解决，仍需检查机械臂接收与控制链路。

## 实现边界

保留原 Jetson 重启后的旧主机服务清理分支。新增分支只接受主机遥操服务已停止、
本地主臂进程不存在、从端仅残留已知遥操进程的情况。故障限于动作超时或 CAN
反馈中断（位 1/2/3）；急停和其他故障不能借此入口恢复。网关已退出的部分清理
可在严格进程身份和断电核验下继续。

要求操作者明确确认断电，两个完整被动采样均不得有任何电机反馈；无反馈本身
不被解释为已经断电或失能。双读启动身份、服务实例、控制会话及进程启动时间；
动作前再次核对录制器和服务。远端使用 pidfd 对准确的进程发送 SIGTERM，拒绝
进程替换、额外未核验子进程；不使用模糊 pkill、进程组信号或自动 SIGKILL。

清理前后证据保存在主机仓库 `work/power-off-recovery/`。保留原故障证据，
不补造失能回执。只有清理后复查为空控制栈、身份未变时才报告成功。

离线回归验证恢复判定、身份变化、错误/缺失反馈、无确认拒绝、部分清理、保留
故障证据，以及使用两个无硬件测试进程确认只终止指定 PID。真机断电清理和
重新启动尚待现场验收。
