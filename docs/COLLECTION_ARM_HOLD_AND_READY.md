# 左臂保持与右臂起始位：使用说明及验收记录

更新：2026-09-18，右主从双端回位修订版。入口仍为桌面“启动蘑菇采集控制台”。

本修订已完成软件测试与编译，尚未进行新版双端真机回位验收；下方原版实机记录仅适用于“右从臂回位”的上一版。部署后需重启控制栈和界面才生效。当前保持姿态不会因更新文件而自动运动。

## 实际操作

1. 等待遥操显示 RUNNING，先用左主臂将左从臂移动到菌棒旁并夹稳。
2. 点击“保持左臂及夹爪”。看到“保持中”后，可以松开左主臂；左从臂继续保持当时的关节与夹爪目标，右臂继续跟随。
3. 第一次采集或更换作业布置时，将右臂遥操到合适的采摘准备位置，让两端都静止，点击“保存主从起始位”。同时保存右主臂、右从臂及两端夹爪。覆盖原位置会弹出确认。
4. 下一条右臂采集前，先将采下物体放好，松开右主臂和主夹爪，点击“主从一起回位”。确认两端路径都没有人体、菌棒、货架等阻挡。右主从臂采用共同进度的低速轨迹返回，各自恢复保存的姿态和夹爪开合。此时不能开始录制。
5. 界面依次显示“等待主臂控制确认”“主从一起运动”“确认恢复跟随中”。两端都到位并稳定后，自动解除主臂回位伺服、恢复遥操，不再需要正常流程中的手动对齐。等到显示“跟随主臂”再操作；不会自动开始录制。
6. 确认右臂 READY 和单朵目标，点击“开始录制右臂”。动作与三路 RGB-D 保存到 Jetson。回位和主臂重新对齐过程不进入本条数据。
7. 点击“成功并保存”“失败并保存”或“中止本条”。封装期间仍保持左臂，右臂遥操继续；封装完成后可以再次回位采下一条。
8. 需要重新调整菌棒时，将左主臂及主夹爪对齐到保持目标，点击“对齐后恢复左臂跟随”。录制或封装期间不能解除保持。

右臂回位过程中可点击“停止双端回位”。双端停止并保持，不自动恢复跟随。异常后的恢复与正常到位不同：检查两端状态，再点击“异常后恢复跟随”。若未对齐，会先解除主臂伺服，主臂恢复重力补偿，但从臂继续保持；这时可手动对齐再点一次，也可以重新点击“主从一起回位”。不要强行拖拽仍在保持的主臂。新的显式回位请求会先确认清除旧伺服状态，再重新接管；网络恢复不会自动重试。回位期间关闭窗口会先请求停止回位，确认保持后再关闭窗口。

结束录制、关闭采集窗口，不会自动解除左臂保持，也不会使机械臂断力。

## 起始位保存与适用范围

Jetson 文件：`/home/nvidia/openarm-rgbd-runtime/right-start-pose.json`。

文件保存右从臂七关节、夹爪的目标值和实测值，右主臂实测关节和夹爪，以及型号、版本和时间。重启后保留。新版 schema_version=2；旧版文件缺少主臂姿态，必须重新保存，不能推断或静默迁移。旧文件保持原样并另行备份，不会在启动时自动覆盖。

位置以机械臂基座为参考。移动底盘、升降杆或改变夹指/负载后，应重新检查起始位及回位路径。回位采用关节插值，不具备货架避障能力。

## 实现细节

- 左臂保持锁存正在下发的目标，而不是将夹爪目标改成受阻时的实测开度，以保留原有夹持预紧。主臂动作不再覆盖该目标。
- 左主臂的双边反馈在保持期间置零，原有重力补偿继续工作。切换左臂时不重置右臂的力反馈参考。
- 右臂保存起始位要求主从反馈健康且静止；文件通过临时文件、fsync 和原子替换保存。检查有限数值、v10 右臂限位（包含 J2 的 +π/2 偏置）、型号及目标跟踪误差；保存的主臂姿态与从臂目标差不得超过 0.06 rad。
- 回位使用五次平滑插值，关节目标峰值速度不超过 0.15 rad/s，夹爪目标不超过 0.25 rad/s。时间至少 2 秒；到位误差要求关节 ≤0.06 rad、夹爪 ≤0.1 rad，并稳定 0.5 秒。
- 关节目标跟踪误差超过 0.20 rad 或到达轨迹时间后再等 8 秒仍未到位，停止回位并保持。网络、看门狗许可或任一臂反馈变旧时，立即取消回位；网络恢复不会自动继续。
- 双端使用同一五次插值进度，但分别从各自当前位置返回各自保存姿态。先保持两端，等待主机实际控制线程上报伺服已启用，才开始推进轨迹。控制确认超时 2 秒则中止。
- 完成要求从臂到位、主臂与从臂目标（包括夹爪）差值 ≤0.06 rad，并稳定 0.5 秒。随后请求主机退出回位伺服，收到实际释放确认后才进入跟随及限速过渡。任何阶段未完成都禁止录制。
- 主机 C++ 控制器新增仅主端启用的独立回位输入，使用原有归位 PD 增益及重力补偿；关节限速 0.15 rad/s、夹爪 0.25 rad/s，回位期间不叠加力反馈。100 ms 没有新的回位目标或关节跟踪误差超过 0.20 rad 时，锁存实测位置保持；更新旧目标不能解除故障。
- 主机 UDP 网关校验 Jetson 地址、应用会话、状态包序号和动作回执新鲜度，丢弃乱序/旧会话状态。主臂反馈超过 100 ms 未更新时，不再发送伪装新鲜的动作。
- 录制管理器在创建正式左右 episode 前向 Jetson 控制器申请带标识的录制锁。右臂录制要求左臂保持、右臂跟随、已保存起始位且实际关节距该起始位 ≤0.07 rad。自动回位或过渡期间拒绝开始。
- 从准备录制到封装完成，禁止回位、覆盖起始位和解除保持。录制结束不停止遥操；管理器记录开始时的保持状态和起始位到 `episode.json` 的 `collection_motion_at_start`。
- 管理器在录制过程中检查控制器状态和录制锁；控制许可丢失则请求结束该条数据。
- 左右臂反馈时间分别记录，任一臂反馈停止都不能被另一臂的新反馈掩盖。
- UDP 协议升级为 v3：状态包含主臂回位目标及保持标志，动作包含主机物理控制器的伺服确认状态。主从必须配套升级，v2/v3 不混用。启动脚本检查 Python 协议接口和主机二进制功能标记。

当前仍是位置保持，不是指尖恒力控制。没有新增指尖力传感器；保持预紧不等于已经确认菌棒无滑动，也不能补偿掉电后的失力。
